02 — SentinelNodeMonitoring & automation

Know when a service fails.
And when the signal stops.

A monitoring application that turns HTTP checks into actionable incidents, recovery history and notification delivery. It demonstrates Python automation and operational tools that retain their state through interruptions.

PythonConcurrent HTTP checksSQLiteGitHub Actions
Run Sentinel ↗Read the source ↗

Self-directed project · A working single-operator app for your computer or server, with a separate local demo. Live AWS operation remains unverified.

The workflow

Configure → check → investigate → recover → export. Saved notes and delivery attempts survive a restart.

The decision

When telemetry stops, mark the observation as unknown and suppress misleading health counts.

The evidence

Run the packaged application, follow a recorded incident in the lab, or inspect the checks for service failures, retries, persistence and recovery.

Inspect the checks ↗
Inside the application +

Recovery doesn’t erase the outage.

Add and edit services, pause checks, and investigate failures. Acknowledgement records your response; a healthy check confirms recovery. Incident notes remain. Failed webhook delivery has a separate journal and deliberate retry action. Guided setup keeps advanced options optional. Inspect exact response times with the chart’s pointer or keyboard controls. The demo exercises the same application against loopback services.

Repeatable, with clear limits.

The portable Python app retains configuration and history in SQLite, exports observations, and restores database backups with monitoring paused for inspection. Administration stays on loopback. The screenshots show the original incident lab; the quick browser replay uses its recorded evidence. The separate AWS path remains unverified in live operation.
