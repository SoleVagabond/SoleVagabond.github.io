The problem

A listing is only
the beginning.

Job information arrives with different formats, duplicate vacancies, uncertain pay and stale application links. Once a person finds a role, they still need to remember the search, compare it with other options and keep their next action organized.

I built the collection and quality pipeline alongside the job seeker's workspace, so the product can explain its results and carry useful work forward.

01 / From discovery to follow-through

One search.
A connected workspace.

  1. 01 / Discover

    Search on your terms.

    Keywords, US geography, ZIP and radius, remote work, pay, occupation, source and experience filters.

  2. 02 / Keep

    Save the useful parts.

    Save a job, compare opportunities, or preserve a complete search with editable filters.

  3. 03 / Act

    Make the next step visible.

    Track application stages, follow-ups, interview plans, document versions and notes.

  4. 04 / Return

    Pick up your work.

    Persistent accounts bring guest activity into a private workspace, with session controls, recovery and export.

A workspace belongs to its user.

Username/password accounts, guest-data migration, hashed recovery and session credentials, device revocation, workspace export and account deletion are implemented. Account data is kept separate from public search results.

Ingestion reliability

Resume the work.
Don't skip a page.

Workday, Oracle Cloud and Lever imports use durable checkpoints. A successful page commits its postings and continuation together; a failed write cannot advance past unfinished work.

Changing offset feeds need care: a resumed scan does not automatically retire unseen jobs, because their position may have shifted.

Data integrity

Keep the dates
honest.

The original posting date, last observation at the source and application-link verification are different facts. The interface keeps them distinct rather than making a refreshed old listing look newly posted.

Source attribution, deduplication, occupation matching and pay provenance support more useful results.

Execution & operations

Give background work
its own boundaries.

Ingestion runs separately from the web process. Redis coordinates budgets and queues; a bounded worker pool moves search computation off the request thread.

The current SQLite architecture is designed for one durable host. Backup tools and deployment checks are implemented; distributed hosting is not claimed.

Personal work

A failed request
shouldn't erase a draft.

Saved-search edits preserve unknown filter fields and retain drafts after failed saves. Account changes clear workspace-related browser caches.

Passwords use salted asynchronous scrypt, while session and recovery credentials are stored as hashes.

Geography & remote eligibility

Remote doesn't mean
anywhere.

A remote vacancy can still be restricted to a particular country. Structured employer addresses and workplace settings now take precedence over broad remote flags, while multi-location roles retain legitimate US offices.

A source-backed repair corrected 202 existing records across six employers. Original posting dates and saved references were preserved; an absent feed entry was not treated as proof that a role had closed.

Search performance

Search the words.
Then narrow the results.

A combined keyword, source and remote filter exposed a query that repeatedly scanned text for individual records. Starting with the full-text index corrected the query plan.

The measured local search completed in about 0.3 seconds after the fix. That is a result for the investigated query on the local inventory, not a public-service latency guarantee.

What was checked

Latest recorded verification, October 19, 2026: all 705 regression tests passed on Node.js 22 and 24. Source-safety, lint, document conversion and backup/restore checks also passed. The local production build passed; the dependency audit still blocks the separate CI build.

Browser verification on October 17 covered selected save, tracker and saved-search journeys, with mobile checks at 390px. Those screenshots represent that interface checkpoint; the later test count is a separate verification record.

Earlier real-feed verification on October 15 refreshed two consecutive pages of 100 existing Lever postings in separate processes, advancing a saved checkpoint from 0 to 100 to 200.

What remains

The dependency audit has unresolved upstream advisories. Public hosting, sustained inventory freshness, a deployment restore and real email delivery still need operational verification. No public traffic or uptime claim is made.
